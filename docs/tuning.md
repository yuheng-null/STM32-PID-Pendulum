# 双环 PID 的整定过程（2026-10-10）

本文记录这套倒立摆**从默认参数到调好**的完整过程：用了什么方法、量到了什么数、
中间修掉了哪两个 bug、以及几条**在真机上才学得到**的方法学教训。

**面向读者**：接着往下做这个项目的人（或未来的自己）。
不要求读过控制理论，但需要知道双环串级是怎么分工的 —— 那部分在
[control.h](../app/control/control.h) 的文件头，本文不重复。

**结果**：平衡时角度偏差中位 **约 0.4~0.8°**（5~9.5 码 / 12.22 码每度），
稳态从不打到 PWM 限幅，连续运行 20 秒以上不倒。
演示见 [docs/media/inverted-pendulum-demo.mp4](media/inverted-pendulum-demo.mp4)。

---

## 一、要调的到底是什么

两环串级的两个 PID，加上一个静摩擦补偿：

```
外环（位置环，50 ms）  →  输出「角度修正量」（±100 码），去挪内环的目标
内环（角度环，  5 ms）  →  输出 PWM（±1800）
OFFSET                 →  输出的过零补偿（PWM 码）
```

可在线改的参数共 12 个，但**这次只动了三个**（`OFFSET`、`AKD`、`PKP` 系列）。
其余保持默认，原因见第五节。

---

## 二、方法：为什么这次"不倒不甩臂"就能调

**这是本次最关键的一条经验。**

常规调倒立摆的流程很折磨人：改一组参数 → 启摆 → 摆杆甩起来 → 看几秒 → 倒了 →
把它放回下垂、再来一次。每次都要全功率甩一遍，慢、危险、机构磨损大。

**但不需要这样。** 摆杆放在**平衡点**上时（即正好竖直向上），靠铰链的摩擦
它**能自己停住不动** —— 用户的原话是"马戏团的平衡大师用指尖顶起一个物体"。
这就给了一条捷径：

> **把摆杆放正 → `RUN` 进闭环 → 保持运行 → 在运行中改参数、一边跑一边量。**

好处：

- **不甩臂**。没有启摆脉冲、没有甩飞风险，机构受力小得多。
- **不用反复摆位**。一次 `RUN` 可以连续跑几分钟，在中间扫十几组参数。
- **工况就是关心的工况**。用户抱怨的"平衡时抖"，本来就该在平衡态下量。

实现上只需要确认一件事：在 1 ms 中断外面改这些 float 参数是安全的。
`control.c` 里原本就有这段论证 —— 参数是 32 位对齐的 float，Cortex-M3 上单条 `STR`
写入不会撕裂，中断里读到的要么是旧值要么是新值，都是合法的浮点数；
而且一次只改一个字段，不存在"多个字段必须同时生效"的需求。
**这次的新用法（运行中连续改）没有突破那个论证的前提**，所以直接用了。

> ⚠️ 前提是**摆杆先得立在平衡点上**。放不正就立不住，只能回去用启摆。
> 这台设备实测：放得足够垂直时能稳定站住十几秒到几十秒，够跑完一轮扫描。

## 三、工具与判据

### 脚本（都在 [tools/](../tools/)）

| 脚本 | 干什么 |
| --- | --- |
| [console_test.py](../tools/console_test.py) | 协议回归，30+ 项断言。改完协议先跑它，**它不会动电机** |
| [offset_sweep.py](../tools/offset_sweep.py) | 在已经立住的状态下，运行中扫一个参数、分段统计 |
| [trial.py](../tools/trial.py) | 一次完整试验（设参数 → 启摆 → 收流 → 报指标 → 停机），带静定等待 |
| [swing_probe.py](../tools/swing_probe.py) | 只观测一次启摆，原样打印轨迹末尾 |

### 看哪几个数

`STREAM` 每 20 ms 吐一行 8 列（`ANGLE, POS, SPD, ATAR, AOUT, POUT, PWM, RUN`）。
从里面算四个指标：

| 指标 | 含义 | 为什么选它 |
| --- | --- | --- |
| `dev 中位` | 平衡时 `\|ANGLE - CENTER\|` 的中位数（ADC 码） | 直接对应用户看得见的"摆杆晃多大" |
| `dev 标准差` | 同上，波动成分 | 中位相同的话，标准差小的那个更"稳" |
| `PWM 中位` | 电机的平均输出 | 太大说明一直在使劲 |
| **`PWM 标准差` / `相邻跳变`** | 输出的波动 / 逐样本跳变 | **本次最有分辨力的指标**，见下 |

`PWM 标准差` 在这次测量里**重复性最好**：同一组参数连测两次，90 码那组拿到
161.0 和 161.5，几乎一样；而低值那组在 79~100 之间。相比之下 `dev 中位`
同一组两次能差 2 倍（5.0 和 9.5）。

> **教训**：多个指标里，要挑那个**重复性最好**的当主判据，
> 否则会在噪声里做决定。这件事本身就得靠"重复测"才能发现。

### 安全兜底（必须有）

所有会驱动电机的脚本都带 `|POS|` 看门狗：横杆累计位置超限（默认 1200 边沿 ≈ 3 圈）
立刻 `STOP`。**这不是可选项** —— 位置是累积量，外环参数不对时横杆会一直转，
能把电源线绞断（[control.h](../app/control/control.h) 里写着"硬件上真的会"）。

## 四、过程中修掉的两个 bug（比调参本身更值钱）

这两个都不是推导出来的，是**真机上量出来、并且先撞了墙**才发现的。

### bug 1：位置环的增益被错了 18 倍

**现象**：摆杆能立住，但一直**满量程抖**，`POUT` 全程钉在 ±100 限幅上。

**根因**：把参考工程的增益整组乘了 18。但 ×18 这条规则**只对输出直接喂 PWM 的量成立**：

```
角度环：输出 = PWM          → 参考满量程 100、本机 1800 → 要 ×18
OFFSET / SWP：是占空比       → 同上 → 要 ×18
位置环：输出 = 内环的角度目标 → 两边都是 ±100 码      → **不乘**
```

`PKP` 取 9.36（=0.52×18）之后，位置误差只要 **11 码**就把外环顶死，
外环退化成 bang-bang 控制器。同一段 12 秒轨迹，只改这一组增益：

| | `\|ANGLE-2086\|` 中位 | `\|PWM\|` 中位 | PWM 打满比例 |
| --- | --- | --- | --- |
| `PKP=9.36`（错） | 126 码 ≈ 10° | 412 | 持续打满 1890 |
| `PKP=0.52`（对） | **11 码 ≈ 0.9°** | **150** | **0%** |

**差一个数量级。**

> **同一条规则还有个连带项**：位置环的积分限幅取 `out_max / ki`。
> `ki` 从 0.18 改回 0.01 之后，限幅也得从 500 改成 10000 ——
> 否则 `ki × integ` 最多只有 5 码，**积分被悄悄废掉，且不报任何错**。
> 这类"改了 A 忘了跟着改 B、而且静默失效"的坑，本工程踩过不止一次。

### bug 2：`SWING` 的"已在窗口内就直接进 PID"是错的

**现象**：发 `SWING` 之后不但没启摆，电机反而猛冲、把摆杆甩飞。

**根因**：原来有一条捷径 —— 角度落在 `CENTER ± START`（±150）内就直接进双环。
但那次摆杆在前一轮结束之后**还在慢慢摆动**，路过窗口时静息读数一度是 **1949**
（在 [1936, 2236] 内），于是"正在摆动的摆杆"被当成了"已经立好"。

**某一瞬间落在窗口内，既不等于摆杆是立着的，也不等于它是静止的。**

**已做的修正**：`SWING` 改成**无条件启摆**，不检查角度、不猜姿态；
要"扶好再启动"用 `RUN`（那条路径的准入检查没变）。

> ⚠️ **但这个修正并不彻底，必须知道**：交棒判定用的是**同一个**"落在窗口内"的条件，
> 所以摆杆本来就立着时，`SWING` 进去 5 ms 内仍会被接走。
> "无条件启摆"去掉的只是**事前**的预判，不代表交棒条件本身变可靠了。
> 要动它，得先想清楚**怎么独立证明"杆是立着的"** —— 见第七节。

## 五、调参记录

所有扫描都是**在已经立住的状态下、运行中改参数**做的（方法见第二节）。

### 5.1 `OFFSET`（静摩擦补偿）：90 → **30**

**为什么怀疑它**：`apply_motor()` 的写法是"输出为正就 `+offset`、为负就 `−offset`"。
所以在平衡点附近**输出一过零，加在电机上的占空比就从 +90 跳到 −90**（5% 的台阶）——
而平衡时输出本来就在零附近来回穿，**等于每穿一次就给电机一脚**。
这正是 `control.c` 里自己写的"太大 → 摆杆高频抖动"，也是当初标注"调参阶段再细调"的那一项。

**测量**（每段 8 秒 ≈ 400 个样本；`|` 分隔的是**同一取值的重复测量**）：

| `OFFSET` | `dev` 中位 | `PWM` 标准差 | 说明 |
| --- | --- | --- | --- |
| 90 | 14.0 \| 14.5 \| 13.0 | 164.0 \| 161.0 \| 161.5 | 三次一致，**明显偏大** |
| 60 | 12.0 | 126.7 | |
| 55 | 13.0 | 140.6 | |
| 50 | 14.0 | 144.7 | |
| 45 | 6.5 | 104.7 | |
| 40 | 11.5 | 127.7 | |
| 35 | 10.0 | 119.9 | |
| **30** | 6.0 \| 5.0 \| 9.5 | 96.0 \| 78.7 \| 100.0 | **取这个** |
| 25 | 7.0 | 98.2 | |
| 20 | 7.0 \| 9.5 \| 9.0 | 94.3 \| 95.6 \| 92.4 | |
| 0 | 10.0 | 89.6 | **反而更差**：死区跨不过去 |

**结论**：90 明显偏大；20~30 是一个平台，取平台中间的 30。降到 0 反而变差，
与控制环注释里写的"太小 → 横杆低频抖动（死区没被跨过去）"一致 —— 两个方向都会坏。

> ⚠️ 低值之间的差异**已经淹在噪声里**了（30 的三次是 6.0、5.0、9.5），
> 再往细里抠没有意义。**停在这里是有依据的，不是偷懒。**

### 5.2 `AKD`（角度环微分）：7.38 → **12.0**

**为什么怀疑它**：微分项在放大 ADC 噪声（±8 码的噪声 × Kd 就是几十码的 PWM 抖动）。

**测量**（每段 12 秒，`OFFSET` 固定 30）：

| `AKD` | `dev` 中位 | **`dev` 标准差** | `PWM` 相邻跳变 |
| --- | --- | --- | --- |
| 7.38 | 10.0 \| 7.0 | 10.2 \| 9.1 | 63 \| 59 |
| 12.0 | 8.5 \| 7.0 | **7.8 \| 8.2** | 91 \| 91 |
| 3.0 | 10.0 \| 8.0 | 12.1 \| 12.4 | 45 \| 38 |

**结论**：

- **加大 Kd 有效**：`dev` 标准差两次重复都比 7.38 小（约 15~20%）。
  代价是 `PWM` 相邻跳变大了约 50%（微分项确实在放大噪声）。
- **减小 Kd 明显更差**（3.0 那组两次都最差，标准差 12.1 / 12.4）。
  所以 **Kd 的阻尼是在干实事的，不能因为"它在放大噪声"就把它调小** ——
  这是我一开始的直觉，被数据否掉了。
  有意思的是 Kd 调小时 `PWM` 跳变反而**更小**（45/38），
  说明"输出抖不抖"和"摆杆抖不抖"是两回事，别用前者代替后者去判断。

### 5.3 没动的参数

| 参数 | 保持 | 为什么 |
| --- | --- | --- |
| `AKP` / `AKI` | 4.50 / 0.162 | 稳态偏差中位已经只有几个码，没有继续压的余地 |
| `PKP` / `PKI` / `PKD` | 0.52 / 0.01 / 4.56 | 修掉 ×18 之后回到官方原值，位置漂移一直在 ±10 码内 |
| `CENTER` | 2086 | 手扶实测的标定值，没重测 |
| `RANGE` / `START` | 500 / 150 | 两个判定窗口，与本次"平衡时抖"无关 |

## 六、方法学教训（真机上才学得到的）

### 6.1 单次、单方向、不重复的扫描分不出信号和漂移

第一轮扫 `OFFSET` 是**按参数从大到小顺序**做的，结果看起来"越扫越好"，
像是 OFFSET 越小越好。**改成交错顺序 + 同一取值重复之后，形状完全变了** ——
原来的"趋势"里混进了时间成分（机构在慢慢稳定）。

这直接影响了结论：第一轮会把最优值定在 0，而真值是 20~30。

> **怎么做**：交错顺序（高-低-高-低），同一取值至少重复两次，
> 看重复之间是否一致。这次 `PWM 标准差` 在 90 上重复到 161.0 / 161.5，
> 在 20 上重复到 94.3 / 95.6 / 92.4 —— 这才叫"这个差别是实的"。

### 6.2 测试脚本不要写死默认值

`console_test.py` 里"恢复默认参数"原来是一串**写死的常量**。
位置环默认值改过之后那串常量没跟着改，于是**每跑一次回归就把运行中的参数改回错的**。

现象极具迷惑性：**"调完参、测一次，反而更抖了"** ——
而 `GET ALL` 读出来的数字也确实变了，只是没人记得住默认值该是多少。

**已改成**：开头用 `GET ALL` 做快照，结束时按快照回滚。测试不再是"另一个事实来源"。

### 6.3 测试不能假设进来时环境是干净的

同一个脚本里，`SET START 1` 忘了还原，导致**"第一次跑通过、第二次就挂"**；
而 6.2 的快照机制又忠实地把这个脏值保存下去，**自我延续**。

**已改成**：每个用例自己把要用的参数设好，不依赖环境。

### 6.4 「能测就别推」——包括"怀疑自己的数据"

过程中我一度断言"自由摆杆不可能在竖直位停十几秒，所以那两次的读数是无效的、
数据作废"。**这个断言是错的** —— 摆杆放在平衡点上时确实能自己停住（第二节）。
差点因此扔掉两组好数据。

拿不准摆杆的物理姿态时，**要问看得见的人**，不要用角度读数去判断角度读数自己可不可靠 ——
那是循环论证。（用户就在旁边，一句话的事。）

```
AKP=4.500  AKI=0.162  AKD=12.000
PKP=0.520  PKI=0.010  PKD=4.560
CENTER=2086  RANGE=500  START=150
OFFSET=30.000  SWP=630.000  SWT=100.000
```

| 指标 | 值 |
| --- | --- |
| 平衡时 `\|ANGLE-2086\|` 中位 | **5 ~ 9.5 码 ≈ 0.4 ~ 0.8°** |
| 同上，标准差 | 7.8 ~ 9.5 码 |
| `\|PWM\|` 中位 | 约 30 ~ 40 / 1800（≈ 2%） |
| PWM 打满比例 | **0%** |
| 横杆位置漂移 | ±10 码（几乎不动） |
| 启摆接住时间 | ≈ 0.7 s |
| 连续运行 | 20 秒以上不倒 |

**验证方式与其限度**（说清楚，免得被当成比实际更强的结论）：

- 上表数据来自"已经立住、运行中扫参数"的分段测量，**每一段都是最终配置**。
- 烧录后 `GET ALL` 确认 `AKD=12.000`、`OFFSET=30.000` 已随固件生效。
- ⚠️ **"开机 → 启摆 → 平衡"这条完整链路，没有用最终固件单独复跑一遍**。

## 八、还没做的 / 已知问题

1. **交棒条件仍不够可靠**（见第四节 bug 2 的警告）。
   现在的判据是"角度落在 `START` 窗口内连续 5 ms"。缺一条**独立**的证据来证明
   "杆真的立着"。可行的方向：要求"进窗口后横杆确实被扰动过"，
   或引入角速度判据。**动它之前先想清楚怎么证伪**，否则会把现在能用的东西弄坏。
2. **接住那一瞬间的瞬态**：从下垂启摆时，角度偏差峰值约 200~300 码（≈16~24°），
   稳态才降到 1° 以内。要压这个瞬态可以试 `SWP` / `SWT` / 再调角度环，
   但每次都要全功率启摆，风险比这次用的方法大得多。
3. **`CENTER` 没重测**。2086 是早期手扶实测值；盲区一节里
   （[control.h](../app/control/control.h)）记着一条未验证的残留风险：
   支架若不竖直，"自由下垂"读数会随横杆方位变化。这次没碰。
4. **没有自动启摆之外的"自动重试"**：倒下保护停机后就停在 STOP，需要再发一次 `SWING`。

## 附：复现本次调参的完整命令

```bash
# 0) 把摆杆放到竖直平衡点，让它自己站住

# 1) 协议回归（不动电机）
python tools/console_test.py COM7

# 2) 进闭环 —— 注意是 RUN 不是 SWING（SWING 会踢它）
python -c "import serial,time; s=serial.Serial('COM7',115200); time.sleep(.3); \
           s.write(b'RUN\r\n')"

# 3) 运行中扫 OFFSET：交错顺序 + 重复，别顺序扫
python tools/offset_sweep.py COM7 --param OFFSET \
       --vals 90,30,90,30,20,20 --seg 8 --keep

# 4) 固定住 OFFSET，再扫 AKD
python tools/offset_sweep.py COM7 --param AKD --fix OFFSET=30 \
       --vals 7.38,12,7.38,12 --seg 12 --keep

# 5) 把选中的值写进 control.c 的默认值，重编重烧
```
