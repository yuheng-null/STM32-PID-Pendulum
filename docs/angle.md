# 角度传感器（BSP Angle）实现详解

本文逐层拆解本仓库倒立摆角度传感器的实现：为什么这个套件用**电位器**而不是陀螺仪、
333° 有效角和盲区是怎么回事、驱动层为什么**不提供"角度是多少度"**、
怎么标定中心值、以及**为什么不能用理想值 2048**。

**面向读者**：嵌入式初学者。假设你会 C（结构体、指针），
但不要求懂 ADC 的寄存器细节（ADC 原理见 [pot.md](pot.md)，本文只讲两者不同的地方）。

**配套代码**：

| 文件 | 层 | 职责 |
| --- | --- | --- |
| [PID_Pendulum.ioc](../PID_Pendulum.ioc) | CubeMX | ADC1 的声明（单通道 IN8、序列长度 1） |
| [Core/Src/main.c](../Core/Src/main.c) 生成部分 | CubeMX 生成 | `MX_ADC1_Init()` |
| [Core/Src/stm32f1xx_hal_msp.c](../Core/Src/stm32f1xx_hal_msp.c) | CubeMX 生成 | **ADC1 时钟使能、PB0 配成模拟输入** |
| [bsp/angle/bsp_angle.h](../bsp/angle/bsp_angle.h) · [.c](../bsp/angle/bsp_angle.c) | BSP | 自校准、单通道采样、原始值/电压换算 |
| [Core/Src/main.c](../Core/Src/main.c) | 应用 | 5 ms 采样调度、标定值记录 |

## 一、要解决什么问题

### 1.1 需求与约束

倒立摆**内环（角度环）的反馈**：摆杆相对竖直方向偏了多少。

**这是整个项目里最要紧的一个反馈量**——外环（位置环）的输出是内环的目标值，
而内环直接驱动电机。角度测不准，整机不可能稳。

先把**手上的资源和限制**列清楚：

| 问题 | 答案 |
| --- | --- |
| 传感器是什么？ | **不是** MPU6050，**也不是** AS5600，而是**一只 360° 电位器**（SV01A103AEA01R00，10K） |
| 怎么确认的？ | 套件手册 §3.4 明确写了「本套件的角度传感器采用的是电位器测角度的方案」；原理图上 `SENSOR1` 网络接到 PB0 |
| 接在哪个脚？ | **PB0** = `ADC1_IN8` |
| 有效角度？ | **333°**，两端之间有一小段约 27° 的盲区 |
| 谁负责转换？ | **ADC1**（单通道轮询） |
| ADC1 之前在用吗？ | **没有** —— 电位器（[pot.md](pot.md)）当初刻意选了 ADC2，就是为了把 ADC1 让给这个模块 |
| 需要中断/DMA 吗？ | **都不需要**，单通道轮询足够 |

**那个"刻意留出 ADC1"的决定在这里兑现了**：四个旋钮和角度传感器是**两套完全独立的模拟输入**
（前者走 ADC2、后者走 ADC1），互不干扰，也不用抢通道。

### 1.2 该放哪一层

本仓库的分层是 `应用层 → bsp → driver/device → driver/bus → HAL`。

角度传感器和 [电位器](pot.md) 是**同一类东西**——都是"一只电位器接在某个 ADC 通道上，
读出的电压随位置变化"。它直接调 `HAL_ADC_*`，放 BSP 的职责范围内。

→ 放 `bsp/angle/`。

## 二、角度传感器基础：三个必须先搞清的概念

### 2.1 为什么这个套件用电位器

倒立摆测角度有好几种做法，各有取舍：

| 方案 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **电位器**（本套件） | 电阻分压，读电压 | 极便宜、接口简单（1 根模拟线）、绝对位置（上电就知道角度） | 有磨损、有效角 < 360°、精度一般（12 位 ADC ≈ 0.09°） |
| 磁编码器（AS5600） | 磁铁 + 霍尔阵列 | 无接触、360° 全覆盖、分辨率高 | 贵、要 I2C、要装磁铁 |
| 陀螺仪（MPU6050） | 角速度积分 | 无需机械连接 | **会漂移**，要融合加速度计做互补滤波，复杂得多 |

本套件选电位器是**教学取向**：它把"模拟量采集 + 标定 + 零点处理"这条链路
完整暴露出来，而不用先解决 I2C 协议和姿态融合。对学 PID 来说，
**反馈信号的物理形态不是重点，闭环怎么收敛才是重点**。

### 2.2 333° 有效角和盲区

这是一只**旋转电位器**，不是理想的"无限角度传感器"。它的内部构造决定了：

```
        0°                                          360°
        ├──────────────────────────────────────────────┤
        │  有效区间（电阻轨道） 333°  │  盲区 27°  │
        │                              │           │
   raw ≈ 0 ────────────────────► raw ≈ 4095      （读数无效/跳变）
```

- **有效区间 333°**：抽头在电阻轨道上滑动，输出电压随角度**线性**变化
- **盲区约 27°**：轨道两端之间有一段空隙，抽头跨过它时**输出会突变**（甚至浮空）

**这对倒立摆意味着什么**：摆杆的**工作范围就在竖直附近**（参考实现取中心 ±500 LSB ≈ ±41°），
**永远不会进盲区**。所以本模块**不做任何盲区补偿**，正确的做法是应用层做范围检查：

```c
/* 参考实现的做法：超出中心区间就停机 */
if (!(Angle > CENTER_ANGLE - CENTER_RANGE &&
      Angle < CENTER_ANGLE + CENTER_RANGE)) {
    RunState = 0;      /* 摆杆倒了，停 */
}
```

> 如果代码里试图"补偿"盲区，只会把简单问题复杂化——盲区是不可测的区间，
> 没有任何信息可以从读数里恢复出来。

### 2.3 为什么驱动层不给「角度是多少度」

**这是本模块最重要的一个设计决定。**

直觉上，驱动层似乎应该提供 `bsp_angle_degrees()`，返回"偏离竖直多少度"。
但本工程**故意不提供**，只给原始值和电压。

理由是：**"竖直"对应哪个读数，取决于传感器的机械安装相位**——换一台设备就变了，
它**不是这块芯片、这块板子的属性**，而是"这台机器装得怎么样"的属性。

如果把它写进驱动：

| 后果 | 说明 |
| --- | --- |
| 模块不可移植 | 换台设备就得改驱动代码 |
| 违反分工 | 驱动层不应包含"板外"的标定常数 |
| 归属错乱 | 以后有人改机械结构，得去驱动里改常量 |

**所以边界划在这里**：

- **驱动层**：只负责"把电压变成数"（`raw` 0~4095、`millivolt` 0~3300 mV），
  外加一个硬件接线属性（两端接反时的**方向开关**）
- **应用层**：持有中心值 `CENTER_ANGLE` 和可调控区间，做范围检查

参考实现就是这么做的——`main.c` 里一个 `CENTER_ANGLE` 宏，不属于任何驱动。

**而且 PID 根本不需要"度"**：角度环要的是**误差** `raw - CENTER_ANGLE`，
单位是 LSB 还是度都无所谓（增益会把量纲吸收掉）。**引入"度"只会多一次除法和一份取整误差。**

## 三、CubeMX 配了什么

### 3.1 命令行配方

```text
# mx.scratch/recipe_adc1_in8.txt
set mode ADC1 IN8
set pin PB0 ADC1_IN8
set ip parameters ADC1 SamplingTime-0#ChannelRegularConversion ADC_SAMPLETIME_55CYCLES_5
```

三行，但每一行都有讲究：

**① `set mode ADC1 IN8`** —— 模式名就是通道名（`IN0`~`IN15`）。
这一步会**顺便把 rank 0 槽位建好**（`Channel-0 = ADC_CHANNEL_8`、`Rank-0 = 1`），
所以不需要像 ADC2 那样手工追加槽位。

**② `SamplingTime` 键名里的 `#` 要原样写**。
`.ioc` 文件里它是转义的（`SamplingTime-0\#ChannelRegularConversion`），
但在配方（CubeMX 脚本命令）里写不转义的原始形式。这是从工程里已有的 ADC2 配方
（`mx.scratch/recipe_adc2.txt`）对照出来的——**别猜，去翻已经跑通的配方**。

**③ 采样时间 55.5 周期** —— 与电位器同一个理由：电位器抽头是高阻抗源
（这里是 10K），采样电容需要足够时间充满。55.5 周期 @ 12 MHz ≈ 4.6 µs。

**④ 不需要配的东西**（都是默认值，正好是我们要的）：

| 参数 | 值 | 为什么不写 |
| --- | --- | --- |
| `ScanConvMode` | `DISABLE` | 单通道，默认就关 |
| `NbrOfConversion` | `1` | 单通道，默认就是 1 |
| `ContinuousConvMode` | `DISABLE` | 默认关（一问一答） |
| `ExternalTrigConv` | `ADC_SOFTWARE_START` | 默认软件触发 |

> ⚠️ **不要**去显式设 `ScanConvMode` / `EOCSelection` / `DMAContinuousRequests` —— 
> 这几个键在 F1 的 ADC 模型里**不存在**，写了会触发 CubeMX 的 Code Generation 警告
> （[pot.md](pot.md) 的坑表里记过这一条）。

**⑤ ADC 时钟不用碰。** F103 只有**一个** ADCCLK 预分频器（`RCC_CFGR.ADCPRE`），
ADC1 和 ADC2 共用。配 ADC2 时已经设成 `/6 → 12 MHz`（低于 14 MHz 上限），
**ADC1 直接复用**，重复设置反而可能出错。

### 3.2 生成出来的代码

**`MX_ADC1_Init()`**（[Core/Src/main.c](../Core/Src/main.c)）：

```c
hadc1.Instance = ADC1;
hadc1.Init.ScanConvMode = ADC_SCAN_DISABLE;      /* 扫描关闭 */
hadc1.Init.ContinuousConvMode = DISABLE;
hadc1.Init.DiscontinuousConvMode = DISABLE;
hadc1.Init.ExternalTrigConv = ADC_SOFTWARE_START;
hadc1.Init.DataAlign = ADC_DATAALIGN_RIGHT;
hadc1.Init.NbrOfConversion = 1;                  /* 序列长度 1 */
if (HAL_ADC_Init(&hadc1) != HAL_OK) { Error_Handler(); }

sConfig.Channel = ADC_CHANNEL_8;
sConfig.Rank = ADC_REGULAR_RANK_1;
sConfig.SamplingTime = ADC_SAMPLETIME_55CYCLES_5;
if (HAL_ADC_ConfigChannel(&hadc1, &sConfig) != HAL_OK) { Error_Handler(); }
```

**`HAL_ADC_MspInit()` —— 这一处是本模块最关键的地方**：

```c
if(hadc->Instance==ADC1)
{
  __HAL_RCC_ADC1_CLK_ENABLE();          /* ← 没有这句，ADC1 根本不工作 */
  __HAL_RCC_GPIOB_CLK_ENABLE();
  /**ADC1 GPIO Configuration
  PB0     ------> ADC1_IN8
  */
  GPIO_InitStruct.Pin = GPIO_PIN_0;
  GPIO_InitStruct.Mode = GPIO_MODE_ANALOG;
  HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
}
else if(hadc->Instance==ADC2)           /* ← 原有的分支，必须保留 */
{
  ...
}
```

**加 ADC1 之前，`HAL_ADC_MspInit()` 里只有 `ADC2` 一个分支。**
这次重新生成之后才多出 ADC1 那一支。

**这件事决定了本模块必须走 CubeMX，不能手写**：

- 手写一个 `ADC_HandleTypeDef hadc1` 变量、手写 `MX_ADC1_Init()` 是**能编译通过**的
- 但 `HAL_ADC_MspInit()` 里没有 ADC1 分支 → `__HAL_RCC_ADC1_CLK_ENABLE()` 不会执行
  → **ADC1 的时钟没开** → 读出来全是垃圾（或者转换永远不完成）**且不报任何错**

而且即使你想手工往生成文件里补那段代码，也违反本工程的根本纪律
（`Core/` 下的内容改了等于没改，下次生成就被覆盖）。

### 3.3 一处 CubeMX 不会做的：CMake 源文件清单

新增 `bsp/angle/bsp_angle.c` 要在顶层 [CMakeLists.txt](../CMakeLists.txt) 的
`target_sources` 和 `target_include_directories` 各加一行。

`cmake/stm32cubemx/CMakeLists.txt` **不需要动**：`stm32f1xx_hal_adc.c` /
`hal_adc_ex.c` 在配 ADC2 时就在清单里了。

顺带一个观察：这次重新生成后 **`Core/Src/stm32f1xx_it.c` 没有任何改动**——
说明没有引入任何中断。这是对的，PWM / 编码器 / 单通道 ADC **一个中断都不需要**。

## 四、手写的部分

### 4.1 先定接口

```c
error_t  bsp_angle_init(void);
error_t  bsp_angle_sample(void);
uint16_t bsp_angle_raw(void);          /* 0 ~ 4095 */
uint16_t bsp_angle_millivolt(void);    /* 0 ~ 3300 mV */
```

**刻意与 `bsp_pot` 完全同形**（`_init` / `_sample` / `_raw` / `_millivolt`）。
调用者从"读四个旋钮"切到"读摆杆角度"时，心智模型不用切换。

### 4.2 为什么不需要每次改通道（和 bsp_pot 的关键差异）

`bsp_pot_sample()` 每采一路都要重配一次通道：

```c
/* bsp_pot.c —— 4 路共用 ADC2，每路都要切 rank 1 */
ADC_ChannelConfTypeDef cfg = {0};
cfg.Channel      = s_pot_channel[i];
cfg.Rank         = ADC_REGULAR_RANK_1;
cfg.SamplingTime = ADC_SAMPLETIME_55CYCLES_5;
HAL_ADC_ConfigChannel(&hadc2, &cfg);
```

而 `bsp_angle_sample()` **不需要**这一步：

```c
/* bsp_angle.c —— 只有一个固定通道，配置在 MX_ADC1_Init() 里就定死了 */
if (HAL_ADC_Start(&hadc1) != HAL_OK) { return ERR_NOT_READY; }
if (HAL_ADC_PollForConversion(&hadc1, BSP_ANGLE_POLL_TIMEOUT_MS) != HAL_OK) { ... }
s_angle_raw = (uint16_t)HAL_ADC_GetValue(&hadc1);
(void)HAL_ADC_Stop(&hadc1);
```

**原因**：电位器要轮流采 4 路，而角度传感器只有 1 路。
通道在初始化时配一次就永远不用改，少三行、少一次寄存器写、也少一处可能写错的地方。

**但采样流程的骨架是一样的**（Start → Poll → GetValue → Stop），
因为两者都属于"序列长度 1、扫描关闭"的配置——**在这种配置下 EOC 才恢复成
"这次转换结束就置位"的正常语义**，`HAL_ADC_PollForConversion()` 才可靠。

> 关于 EOC 在扫描模式下的坑（"整组结束才置位"），
> 那是 [pot.md](pot.md) 花了一整节讲的事，本文不重复。

### 4.3 为什么只能在主循环调用

**这是本模块继承自 `bsp_pot` 的一条硬约束**，写在了头文件的显眼位置：

```c
/**
 * @note ⚠️ **只能在主循环里调用，不要放进中断。**
 *       它内部用 HAL_ADC_PollForConversion()，该函数的超时判断依赖
 *       HAL_GetTick()；而 1 ms 节拍所在的 TIM1 抢占优先级（1）高于
 *       SysTick（15），在节拍任务里 uwTick 根本不涨——一旦这次转换
 *       没有正常完成，等待会**永久卡死**，整个系统从此失去节拍。
 */
```

拆开说清楚这条因果链：

1. `HAL_ADC_PollForConversion()` 的**成功路径**是"EOC 一置位就返回"，约 5.7 µs，
   它**不关心** `HAL_GetTick()`
2. 但它的**失败路径**（转换没能完成）是一个 `while` 循环，靠 `HAL_GetTick()` 判断超时
3. `HAL_GetTick()` 的值由 **SysTick 中断**递增
4. **TIM1（节拍）的抢占优先级是 1，SysTick 是 15** —— 数值越小优先级越高，
   所以 TIM1 会**抢占** SysTick
5. 于是在节拍任务里，只要卡进失败路径，**SysTick 永远进不来**，
   `uwTick` 不涨，超时条件永远不满足 → **死循环**

**结果**：整个系统失去节拍（按键不响应、显示不刷新），而且是在某个特定条件下才触发，
极难复现。

**所以本工程的纪律是**：`bsp_pot_sample()` 和 `bsp_angle_sample()` 一律留在主循环。
这也意味着 **5 ms 的采样周期是由主循环的调度精度保证的，不是硬实时的** ——
对本应用完全够用（摆杆的机械时间常数远大于毫秒级）。

> 如果将来 PID 需要严格的等周期角度采样，正确做法是给 `bsp_angle` 加一对
> **非阻塞接口**（`trigger()` 只调 `HAL_ADC_Start()` 立即返回，`poll()` 只查 EOC 标志、
> 不用 `HAL_GetTick()`），在节拍里 trigger、下一次 tick 读结果。
> 本阶段不做——先跑通阻塞版，把接口形态的变化留到有明确需求时。

### 4.4 镜像 bsp_pot，但不抽公共代码

`bsp_angle` 和 `bsp_pot` 确实有重复：

| 重复的部分 | 行数 |
| --- | --- |
| `Start → Poll → GetValue → Stop` 骨架 | 约 8 行 |
| `raw * 3300 / 4095` 换算 | 2 行 |

**但本工程故意不抽公共层**，理由：

| 理由 | 说明 |
| --- | --- |
| 重复量太小 | 真正重复的不到 10 行，抽出来的接口反而要加配置参数 |
| **语义不同** | pot 是"4 通道轮流切 rank、20 ms、人手拧"；angle 是"单通道固定、可能要 1 ms、带方向标定" |
| 抽象成本 > 重复成本 | 硬抽一个"通用 ADC 通道读取"，两边都要往上挂配置，两边都变难读 |
| 本工程偏好自包含 | 每个模块的注释讲的是**这个模块自己的取舍**，抽公共层会稀释注释的归属 |
| 还没有第三个使用者 | 等第三个出现再抽不迟（Rule of Three） |

**但保持了接口形状一致**——这是"一致性"和"抽象"的分界线：
**名字和行为对齐，实现各自独立。**

（如果真想消掉那 2 行换算，最多在 `driver/common/` 放一个 `static inline` 的
`adc_raw_to_mv()`，**但不要把采样流程抽走**。）

## 五、怎么测试与标定

### 5.1 为什么「编译通过 + 烧录成功」不算验证

对 ADC 尤其要注意：**读数为 0 有两种完全不同的含义**——"引脚上真的是 0 V"
和"这个变量压根没被更新过"（[pot.md](pot.md) 的坑表里记过这个误判）。

所以下面按证据强度分层。

### 5.2 第一层：确认 MSP 里真的有 ADC1 分支

```bash
sed -n '/void HAL_ADC_MspInit/,/^}/p' Core/Src/stm32f1xx_hal_msp.c
```

**必须看到 `if(hadc->Instance==ADC1)` 分支里同时有**：

- `__HAL_RCC_ADC1_CLK_ENABLE()`
- `GPIO_PIN_0` 配成 `GPIO_MODE_ANALOG`（在 GPIOB 上）

**同时 `else if(hadc->Instance==ADC2)` 分支必须还在**（改动不能破坏已有的）。

**这一条如果漏看，后果是"能编译、能烧录、读数是垃圾"** —— 见 3.2 的解释。

### 5.3 第二层：读运行时值（不需要人动手）

```bash
arm-none-eabi-nm build/Debug/PID_Pendulum.elf | grep s_angle_raw
# 20000864 b s_angle_raw

python mx.scratch/pend_watch.py 6
```

连续读能看到读数在**实时刷新**（而不是死值）：

```
    时刻  angle  delta   total  duty   cmd run
   0.6   2086      0   27861     0    20 off
   1.2   2086      0   27861     0    20 off
   ...
   6.3   2086      0   27861     0    20 off
```

摆杆不动时读数稳定（±8 LSB 噪声），说明 ADC 在工作、通道正确。

### 5.4 第三层：标定中心值（需要人配合）

**这是本模块最重要的一步**，因为 `CENTER_ANGLE` 直接决定倒立摆能不能站稳。

**方法一：自由下垂（推荐，无手测误差）**

> 让摆杆**自由下垂、不要用手扶**，等它在阻尼下停稳，读 `bsp_angle_raw()`。

为什么这是**权威方法**：自由悬挂的摆杆，重心必然停在支点**正下方**——
**这就是"竖直"的定义**（由重力给出，与人的目测无关）。等它静止下来读，
得到的就是真值。摆杆自然摆动几秒就会停。

**方法二：手扶竖直（本次用的，有误差）**

本次实测是手扶的，读数 **≈ 2086**。手扶能到什么精度？12.22 LSB/度（见下），
2086 与 2048 差 38 LSB ≈ **3.1°** —— 3° 确实在人的目测能力范围内，
**所以这个值有手测误差，不能当作最终值。**

**参考实现给的经验区间是 1900~2200**，2086 落在区间内，说明安装方向是对的。

> ⚠️ **最终的 `CENTER_ANGLE` 应该用方法一测**。手扶的 2086 可以作为初值，
> 但上电前最好按方法一复核一次。

### 5.5 第四层：量程与线性

**在已知物理位置读三个点**（本次由使用者手测）：

| 位置 | `raw` | 与竖直的差 |
| --- | --- | --- |
| 摆杆竖直（手扶） | 2086 | — |
| 水平向左（逆时针 90°） | 960 | 1126 LSB |
| 水平向右（顺时针 90°） | 3160 | 1074 LSB |

由此推出三件事：

```
每 90° 平均跨度 = ((2086-960) + (3160-2086)) / 2 = 1100 LSB
→ 12.22 LSB/度

满量程 4095 LSB ÷ 12.22 = 335°
手册标称有效角度              = 333°        ← 吻合到 0.6%！

两方向对称性 = |1126 - 1074| / 1100 = 4.7%   ← 在"手测水平"的误差范围内
```

**这个自洽性非常有说服力**：如果 ADC 通道选错了、或者传感器不是手册说的型号，
不可能恰好算出 335° 对上 333°。**这是一条独立于"读数在变"的交叉验证。**

**读数随顺时针转动而增大** —— 这是以后给 PID 定符号要用的方向信息。

### 5.6 为什么不能用理想的 2048

**这是一个值得单独写一节的问题**，因为 2048 看起来很"合理"，实际是个陷阱。

**2048 是什么？** 它是**电位器的电气中点**——由电阻轨道和抽头的**制造**决定
（4095/2 ≈ 2048，量程的几何中心）。

**它和"摆杆竖直"之间没有任何物理必然联系。** 两者是否重合，完全取决于
角度传感器模块装到轴上时的**机械相位**。手册专门强调过：

> 「角度传感器与摆杆的安装需要注意方向，**错误的安装位置会导致倒立摆无法工作**」

**参考实现自己也否定了"用 2048"**：

> 「此值需要根据自己的设备对应更改，**一般在 1900~2200 之间**」
> 「中心角度值不准确会导致摆杆总是有往一个方向跑的趋势」
> 「会导致位置环 PD 控制器有稳态误差」

**注意它给的是一个区间、而不是一个数**。如果 2048 是"理想值"，
这套件就不必让每个使用者去量了——直接写死即可。

**用错中心值会怎样**（假设真竖直是 2086，却用 2048）：

| 后果 | 机理 |
| --- | --- |
| 摆杆稳态偏 3° | 角度环会把摆杆驱动到 `raw = 2048`，而那不是竖直 |
| 摆杆总朝一个方向跑 | 恒定偏差 → 恒定输出偏置 → 位置环持续朝一边修正 |
| 位置环有稳态误差 | 同上 |

**3° 听着小，但角度环的增益很大，这个固定偏置会被放大成明显的漂移。**
参考实现把这条警告写在了宏定义旁边，就是因为踩过。

**所以正确的做法不是"在 2048 和 2086 之间选一个"，而是"换一个没有手测误差的测量方法"**：

> 拿一个**有误差的测量**（手扶竖直）去换一个**未经测量的假设**（2048），
> 不是改进。正确做法是**让摆杆自由下垂**（见 5.4 方法一），
> 用重力定义竖直，把误差消掉。

### 5.7 没验证到什么

| 项目 | 状态 |
| --- | --- |
| **盲区的位置与宽度** | ⬜ 未实测（手册说约 27°，本次没转到那里） |
| **自由下垂的中心值** | ⬜ 未测（本次用的是手扶值 2086，有约 3° 误差） |
| 两端极值（应接近 0 / 4095） | ⬜ 未测（摆杆 360° 自由转动、无机械限位，手测"转到极限"不成立） |
| 温漂 | ⬜ 未测 |

**前两项建议在调 PID 之前补上**——中心值直接决定能否站稳。

## 六、设计取舍一览

| 决定 | 换来什么 | 代价 |
| --- | --- | --- |
| 用 ADC1 而非 ADC2 | 与四个旋钮物理隔离，互不影响 | 需要走 CubeMX 新增外设（MSP 分支只能生成得到） |
| 驱动层不给"度" | 模块可移植、分工清晰、少一次除法和取整误差 | 应用层要自己持有 `CENTER_ANGLE` 并做范围检查 |
| 不做盲区补偿 | 逻辑简单、不假装能恢复不可测的信息 | 应用层必须做范围检查（这也是参考实现的做法） |
| 采样时间 55.5 周期 | 对高阻抗源（10K 电位器）有充分余量 | 单路转换 5.67 µs（相对 5 ms 周期可忽略） |
| 不抽 pot/angle 公共代码 | 两个模块各自可读、注释归属清晰 | 约 10 行重复 |
| 采样放主循环 | 不违反中断"快进快出"（且避免 `HAL_GetTick` 死等） | 采样周期不硬实时（毫秒级抖动，够用） |
| 接口与 bsp_pot 同形 | 心智模型统一 | 无 |

整个模块约 110 行，其中真正的"逻辑"只有采样那 5 行，
其余都是**为正确性付出的成本**——自校准、超时、`s_ready` 守卫、越界处理。

## 附：这次踩过的坑

| 坑 | 现象 | 根因 |
| --- | --- | --- |
| **以为手加 `hadc1` 就行** | 能编译，但读数是垃圾且不报错 | `HAL_ADC_MspInit()` 里原本**只有 ADC2 分支**，ADC1 的时钟不会使能。**必须走 CubeMX 生成** |
| **`#` 在配方里怎么写** | 不确定要不要转义 | `.ioc` 里是 `\#`、配方里是不转义的 `#`。**去翻已经跑通的 ADC2 配方对照** |
| **想显式设 `ScanConvMode`** | 会触发 Code Generation 警告 | 这个键在 F1 的 ADC 模型里不存在（[pot.md](pot.md) 记过） |
| **手扶竖直当成精确值** | 2086 与理想值 2048 差 3°，无法判断是安装偏差还是手抖 | 手测精度就在 3° 量级。**权威方法是自由下垂** |
| **把 `2048` 当"理想中心"** | 会引入固定偏置 → 摆杆朝一边跑、位置环稳态误差 | 2048 是电位器**电气中点**，与机械竖直无关（见 5.6） |

**最后一条最值得记**：`2048` 这个数有一种"天然的合理性"——它是量程的正中间，
看起来就该是"竖直"。但这个合理性是**数学的**，不是**机械的**。

这类"看起来对"的假设是嵌入式里最常见的错误来源：**从"中间值""常见值""别的型号是这样"
推出来的常量，必须回到这台设备自己的定义或实测值上去核对。**
本工程同类的前车之鉴还有一处——[serial.md](serial.md) 里那次 F1 的 USART 参数
误用了别的系列的长名，结果四层检查全绿、生成的初始化函数却少了一半字段。
